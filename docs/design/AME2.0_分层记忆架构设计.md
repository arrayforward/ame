## 1. 1.x 诊断：为什么要 2.0

| 1.x 病症 | 根因（存在论） | 2.0 解法 |
|---|---|---|
| 关键词枢纽能量淹没直接证据（打 max 归一补丁） | 事实/索引/本体混在一张扁平图，**三层语义一个 NodeKind** | 分层拆存储（§3），层间混淆结构性消除 |
| 陈旧结论污染（"我没有联网"被 recall 当真事实） | 助手回答（解释）与用户陈述（事实）无差别入库 | 观测/事实/解释分离 + Reality 标记 + 来源可靠性（§4、§6） |
| 模板问题互相命中（"X 你还记得吗"组团） | 提问被当成记忆内容 | 提问只是观测，**视图在查询时打包 Q→A**（§5） |
| SUPERSEDES 启发式偏宽（df≤5 经验补丁） | 知识冲突无裁决协议 | fold 三序裁决（权威@事件时刻, ts, seq）（§6） |
| 同名实体合并/少计 | 身份靠事后投票（论文预测的 L4 认领路线，系统性少计） | declare 原语 + 计数意图注入；Resolver 退居重认领（§7） |
| 删除 session 语义含糊 | 无所有权概念，"删除"=删目录 | erase vs corrects 两语义 + owner 分片（§8） |
| 每 session 一引擎，记忆断裂、词典重复载 | 隔离单位错（按会话而非按数据主体） | owner 分片 + session=channel（§8） |

核心命题（一句话）：**AME 1.x 把对话当事实存；AME 2.0 把世界当事实存，把对话当认知在查询时临时合成。**

## 2. 存在论基座（设计公理，先于机制写死）

采纳 MES 研讨的**四原语**与存在层/抽象层判据（"有现实孪生体吗？删掉它世界变不变？"）：

```
存在层（有孪生体，append-only，可抹除）
  本体：世界里的对象（游客、景点、茶杯）——id 是数字句柄，无类
  事件：本体的真实变化记录（属性变成了某值）——落章不可刮，冲正用红字
抽象层（无孪生体，删掉世界不变）
  规则：法（人设、导览规则、校验）——定义是数据不是代码
  视图：看（对话记录、recall 证据、助手回答）——观察者为了支撑一次决策的切片
```

三条硬结论直接采用：

1. **体先于变**：先有（软）槽位，事实才有挂载点；无对象的变化不成立；
2. **修正的纯洁性**：被冲销的是本体的属性当前值，事件只被引用（`corrects`）不被改写；
3. **无类**："实体类型"是属性集合的涌现形态，规则按属性存在性匹配——2.0 不设 Event/Entity 节点类型枚举，只有本体/事件/规则/视图四者。

所有权维度与存在论正交（§8）：**什么是什么**（存在论）与**谁有权让它消失**（所有权）分开设计。

## 3. 总体架构：四层存储 + 两域分片

```
                ┌─ 视图层 View（M18）───────────────────────────┐
                │ 查询时合成：证据取证 → Q→A 打包 → 去重 → 装配   │  永不落盘
                └──▲───────────────────────▲────────────────────┘
        recall/合成 │                       │ 索引查询
   ┌────────────────┴───────┐   ┌───────────┴───────────────────┐
   │ 事实层 Fact（M16）       │   │ 索引层 Index（M17）            │  索引=可重建缓存
   │ 属性变化事件流 + fold    │◄──│ 关键词倒排/槽位目录/关联边/画像  │  drop+replay 重建
   │ 物化"当前值"视图         │   │ (co-occurrence/RELATED 可选)   │
   └───────▲─────────────────┘   └───────────▲───────────────────┘
           │ 提取（M1 规则提取器/LLM 提取）     │ replay
   ┌───────┴─────────────────────────────────┴───────────────────┐
   │ 观测层 Observation（M15）                                     │  append-only
   │ 原始言语行为日志：谁(owner)在哪个会话(channel)于何时说了什么    │  per-owner 分片
   └──────────────────────────────────────────────────────────────┘
        ▲ 写入                                    ▲ 公共域（无个人数据主体）
   用户/助手/拍照/声明                              词库/人设规则/导览方案
```

**两域分片**（§8 详述）：个人域按 `owner_id` 物理分片；公共域（词库、规则、导览方案）真共享。

语义阶梯落位：观测= L0→L1 的原料；事实=L3（版本化可回溯）；本体=L4（fold 物化的槽位视图）；规则=L5；视图=L2；价值/意图/社会（L6–L8）本期不进个人记忆核心，仅保留扩展口（§9）。

## 4. 数据模型

### 4.1 观测 Observation（存在层，append-only）

```jsonc
{
  "seq": 100231,              // 全局单调（per-store uint64）
  "ts": 1791976774,           // epoch 秒
  "owner": "tourist-0427",    // 数据主体（分片键）
  "channel": "session-mv7h",  // 会话/渠道（观察面，非所有权）
  "kind": "user",             // user | assistant | vision | declare | note
  "text": "袋子上写了什么呢？",
  "meta": { }                 // 可附：图片路径、坐标、置信度等（普通键）
}
```

纪律：**user 与 assistant 言语都是观测**（言语行为真实发生了）；assistant 观测
**默认不再事实挖掘**——它是解释/视图原料，可靠性低于 user 观测（§6 来源可靠性），
仅在视图打包时作为"问题→回答"对的回答半出现。

### 4.2 事实 Fact / 属性变化事件（存在层，append-only + 冲销）

```jsonc
{
  "seq": 100232,
  "ts": 1791976774,
  "owner": "tourist-0427",
  "entity": "tourist-0427:self",  // 槽位引用："owner:self" / "owner:实体名" / "public:景点X"
  "attr": "上午喝的饮料",
  "value": "龙井",
  "reality": "observed",      // observed | declared | derived
  "confidence": 0.9,          // 提取置信度（declare 恒 1.0）
  "source_obs": 100231,       // 溯源：来自哪条观测（derived 可空=规则推导）
  "corrects": 0               // 非 0 = 冲销哪条 fact（红字，留痕）
}
```

无类：实体身份 = `owner:名` 或 `public:名` 的槽位引用；"车辆/设备/人物"只是
属性集合的涌现形态，不设类型枚举。

### 4.3 索引 Index（抽象层，**可重建缓存**）

关键词倒排（word → obs seq 列表）、槽位目录（名 → 槽位 → 事实 seqs）、
关联边（共现计数 / 词典 RELATED，可选，供联想扩散用）、fold 物化画像
（owner → 槽位 → 当前属性表）。全部可由观测+事实 **replay 重建**；
允许持久化加速载入，但带校验（仿 AC 缓存：size+mtime），不一致即重建。
**索引不是事实，删了不丢信息。**

### 4.4 视图 View（抽象层，**永不落盘**）

```
evidence(query, owner, k) →
  ① 索引召回：事实命中（fold 当前值）∪ 观测全文（BM25-lite，词典扩展）
  ② 打包：命中观测若是 user 提问，自动附其下一条 assistant 观测（"问题 → 回答"）
  ③ 排序：α·词面分 + β·来源可靠性 + γ·半衰期时间分（查询时衰减，不改写基准）
  ④ 去重：文本级（引擎 1.x 已有实现，平移）
assemble(persona, rules, evidence, window) → 提交给 LLM 的上下文
```

1.x 的"整轮打包写记忆"在 2.0 中被**视图时打包**取代：同样的检索收益，零记忆污染。

## 5. 写路径

```
        user 消息 ──┐
        助手回答 ───┼─► ingest_observation(owner, channel, kind, text)
        拍照(vision)─┤        │ append-only，立即落盘（per-owner 分片）
        declare ────┘        ▼
                  事实提取（P0：M1 规则提取器，词典已就位；LLM 提取为可选插件）
                        │ 产出 fact 候选
                        ▼
                  校验三道门（MES 四层校验的裁剪版）：
                    G1 槽位存在性：实体槽位存在或本次声明创建（体先于变）
                    G2 属性字典：attr 在字典内（未登记键进不了事实层；字典按域分治）
                    G3 规则过滤：人设/领域规则否决（非法事实零入库零污染）
                        ▼ 通过
                  append fact（reality=observed/derived + confidence + source_obs）
                        ▼
                  索引增量更新（挂了可整体 replay 重建）
```

要点：**提问与回答都是观测，只有提取出的属性变化才是事实**。"你还记得吗""查一下
天气"这类话永远成不了事实——它提取不出属性变化；搜索结果（kind=search）默认连
观测都不入（仅当轮视图上下文），需要留存时以 `reality=derived` + 短半衰期入观测层。

## 6. 冲突裁决：Reality 标记 + fold + 来源可靠性

**Reality 三值**（一个标记，行为差异收敛于三处：可信度语义/消亡方式/修改方式）：

| | observed（观测到） | declared（声明） | derived（推导） |
|---|---|---|---|
| 可信度 | confidence×来源可靠性，半衰期 | 权威，不衰减，可被新声明**撤销** | 最低，可随时整体废弃重建 |
| 写入 | 用户言语提取 | declare 原语 | 规则/共现推导 |
| 冲突地位 | 中 | **最高（fold 权威序）** | 低 |

**fold 三序裁决**（直接采用 entitytree 工程化版本，权威取事件时刻值，回放逐比特一致）：

```
latest(owner, entity, attr) =
  sort({未冲销的 fact 候选}, key = (authority_rank(reality, source_reliability)@事件时刻,
                                    ts, seq)) 取最后
```

SUPERSEDES 启发式（df≤5 槽位词替换）作废，由 fold 取代。corrects 冲销：原 fact
保留，latest-view 不采纳——审计可回放到任意时刻。

**来源可靠性闭环**（et_sources 模式）：来源（user/assistant/提取器/某 LLM 插件）
持 reliability∈[0.05,1]；事实被召回且用户采纳 → +0.02；用户纠正/冲销 → −0.05
（罚>奖，防刷）；查询打分时以 reliability 折算有效置信度。观测级可靠性初始值：
user 1.0、assistant 0.7、vision 0.9、search 0.6。

**半衰期纪律**（stmb 纪律）：`effective = base × 0.5^((now−ts)/half_life)`，
**基准值永不因时间改写**，衰减纯查询时计算；declared 不衰减；derived 半衰期最短。

## 7. 本体与身份：declare 原语，Resolver 退居重认领

追踪意图协议的落地（四动词映射）：

- **declare**：应用/用户显式声明槽位（"这个游客是 0427""追踪 2 只猫"）——
  计数意图注入，诞生即 confirmed，`reality=declared`，绕过提取置信度；
- **allocate**：事实持续写入槽位（观测提取 + declare + derived）；
- **maintain**：fold 物化视图按增量更新，**身份默认延续，不逐条重判**；
- **reclaim**：仅当混淆证据出现（同名冲突、属性矛盾超限）才触发合并/拆分——
  1.x 的三级投票消歧从"每次写入都跑"退居为"混淆事件后的重认领"。

存疑区保留：冲突未决时新事实挂 disputed 候选，不覆盖 latest-view，等更多证据。
被误合并的纠正 = split（append-only 事件，来源降权进可靠性闭环）。

## 8. 所有权与删除语义（隐私一等公民）

**分片**：观测与事实按 `owner_id` 物理分片（`shards/obs/<owner>.jsonl`、
`shards/fact/<owner>.jsonl`）；公共域记录 `owner="public"`（词库引用、规则、
导览方案声明）。**逻辑统一查询，物理按主体隔离**。

**两种删除语义**：

| 语义 | 适用 | 行为 |
|---|---|---|
| **corrects（冲销）** | 记错了 | 追加红字 fact，原记录保留，latest-view 更新 |
| **erase（抹除）** | 用户删除 session/注销 | 物理删除该 owner/channel 分片全部文件 + **级联清理解释**（索引条目、fold 画像、快照中对应区间）+ 写 tombstone `{owner, erased_at}`（空壳，无内容） |

级联的安全性来自"事实与解释分离"公理：索引/画像全是可重建缓存，删事实即顺带
清理解释，不存在"藏在索引里的残留"。

**channel 级删除**（"删除这个会话"）：删除该 channel 标签下的观测，并级联删除
`source_obs` 指向它们的 fact；owner 其他 channel 的数据不受影响——
对话 App 场景（owner=本机用户）可配置为 channel 级；导游场景（一游客一 owner）
配置为 owner 级。

**公共域不可被个人 erase**；个人观测可以引用/绑定公共槽位（虚实 claim 的
轻量形态：游客拍照事实挂到 `public:景点X`，删游客只删其个人分片，公共景点
事实保留）。

**学习参数隔离**：M14 类边权调整/GateModel 只在 owner 分片内生效；公共参数
只从公共域数据学习；个人文本只过 embedding 推理不入全局训练——erase 之后
不存在"权重里的残留"。

## 9. 扩展口（本期不实现，设计预留）

- **联想扩散**：索引层的关联边（共现/词典 RELATED）预留接口，视图召回可升级
  为"词面+事实+图扩散"三路融合（1.x diffusion 经验直接平移）；
- **LLM 提取插件**：写路径 G1–G3 之后插拔，产物同样走 declare/observed 通道；
- **L6–L8**：价值/意图/社会层——导游 GM（虚体声明+裁判）与游客的 claim 结构
  已在场景层存在，进记忆核心留待多智能体需求明确后按《认知者与 L8 社会层》扩展；
- **多分辨率时间桶**：观测稀疏期粗桶回退（entitytree 已验证模式）。

## 10. 里程碑与验收（判决任务先于机制写死，D1/D4/D6 纪律）

**评测纪律（防自嗨条款，先于一切实现）**：

1. **新机制的"完成"唯一定义 = 测试通过 + bench 数字不谎**。任何"更好/更准/更稳"
   的表述必须附 LoCoMo/LongMemEval 同配置 A/B（同 fixtures、同 LLM 缓存、同 judge），
   否则一律视为未验证；
2. **1.x 基线入档**：现有指标（LoCoMo v3 分 category 表见
   `docs/reports/locomo_report.md`，LME/BEAM 口径见根 README 指标表与
   `docs/reports/longmemeval_report.md`）即 2.0 的对照线，2.0 复跑结果与之一对一
   对比，退化必须逐题归因、写进报告，不许默默带过；
3. **bench 双后端切换**：`bench` 的 `ingest()`/`answer()` 抽象出 backend 开关
   （`--store graph|lmem`），1.x Engine 与 2.0 `mem` 外观跑同一份数据/指标/缓存，
   LLM 失败静默回退 baseline 的既有口径保持；
4. **召回层独立验收**：不只看最终 judge——`evidence_dia_ids` 覆盖率（金标证据
   是否被召回进 top-k）作为 recall 质量的硬指标单独出数，先保证取证，再谈作答；
5. **迭代期抽查、里程碑全量**（测试耗时的现实约束）：
   - **抽样集固定化**：LoCoMo 沿用既有 sample50 回归先例并按 category 分层配额
     （cat2 时序题必入，因其是回归重灾区），LME 按 qtype 分层抽样；抽样种子
     与题单随 commit 固定（`bench/fixtures/sample_*.txt`），改题单属显式变更；
   - **迭代期**：跑抽样集 + 三夹具，用于方向判断与防大退化（覆盖率/ judge 大跌
     即停线）；抽样数字只用于趋势判断，**不作为"提升"声明的依据**；
   - **里程碑验收**：P0/P1 等节点跑全量（LoCoMo 全量、LME 全量 500），抽样集
     与全量结果一并入 `docs/reports/`；
6. **D6 纪律**：每个合入的指标数字必须能从发布产物（commit + 固定种子 +
   缓存）一键重生成，报告记录命令与 commit。

| 里程碑 | 内容 | 验收（全部自动化 + bench 回归） |
|---|---|---|
