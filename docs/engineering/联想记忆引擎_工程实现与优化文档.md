## 一、工程总体思路

### 1.1 实现路线

按设计文档"模块划分与接口定义"，12 个模块 + core 公共层（3.0 已裁 M8 思考 /
M11 反馈 / M14 学习，见 README"3.0 简化版"），全部落地为 C++17 静态库子工程。实现顺序遵循依赖关系：

```
core（公共类型/uid/JSON/日志）
  → M9 存储 / M10 时间 / M13 向量（基础服务）
  → M2 实体解析 / M3 关键词 / M1 提取 / M4 图写入（写入链路）
  → M5 种子 / M6 扩散★ / M7 重排（读取链路）
  → M12 Engine 外观（接入层，六动词 API）
  → bench（基准适配层）+ llm（DeepSeek 接入层）
```

### 1.2 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 语言/标准 | C++17，零第三方依赖 | 嵌入式库定位；WSL g++ 11.4 编译 |
| 存储 | 内存邻接表 + 自研极简 JSON 快照 | 百万边级全内存，扩散微秒级；SQLite/hnswlib 留接口替换 |
| 向量 | IEmbedder 接口 + 哈希 n-gram 实现（占位） | 零依赖离线可跑；语义增强见第七节 |
| 提取 | IExtractor 接口 + 规则实现 + LLM 实现 | 规则兜底，LLM（DeepSeek）提质 |
| 向量检索 | 暴力余弦 topK（ANN 接口后） | 个人级数据量够用；hnswlib 可换 |
| LLM 传输 | curl 子进程 + 磁盘缓存 + 线程池 | 零依赖；缓存使断点续跑零重复扣费 |
| 构建 | 顶层 CMake + add_subdirectory，每模块独立 CMakeLists | 多工程结构，模块可独立理解 |

### 1.3 目录结构


## 二、工程规范

1. **注释规范**：每个文件头部四段式块注释（模块定位/主体思路/关键算法/依赖关系）；每个函数前步骤式伪代码注释，复杂分支体现条件逻辑；行内注释只补不显然处。
2. **测试分层**：每模块独立单元测试可执行 + 端到端测试（test_e2e）+ 基准测试（test_bench）+ LLM 组件测试（test_llm，全 mock 不打真实 API）；`ctest` 一把跑，当前 18/18 全绿。

5. **变更纪律**：重构不改变运行时行为（demo 输出逐字一致验证）；每轮迭代结束必须可编译、测试全绿。

## 三、基准测试适配设计

### 3.1 三基准口径

| 基准 | 数据 | 题型 | 官方指标 |
|---|---|---|---|
| LoCoMo | 10 对话 × ~30 会话，1986 QA | 单跳/多跳/时序/开放域/对抗（cat1~5，编号按不透明整数处理） | F1 / LLM judge |
| LongMemEval-S | 500 题，每题独立 haystack（~115k tokens） | 单会话×3/多会话/时序/知识更新/弃答 | recall@k + LLM judge |
| BEAM | 100 对话（100K~10M tokens），2000 题 | 10 种能力（弃答/矛盾消解/事件排序/信息抽取/指令遵循/知识更新/多跳/偏好/摘要/时序） | nugget 评分（0/0.5/1）+ 事件排序 Kendall tau-b |

### 3.2 离线指标代理（无 LLM 可跑）

- token F1（LoCoMo 口径）；evidence recall@k（answer_session / dia_id 命中）；
- abstention 准确率；nugget 词重叠代理分（F1≥0.6→1，≥0.3→0.5）；Kendall tau-b。
- 预留 `IJudge` / `ILlmClient` 接口，可整体切换为官方 LLM judge 口径。

### 3.3 能力 → 架构机制映射（通用机制，无答案硬编码）

| 基准能力 | 引擎机制 |
|---|---|
| 知识更新 / 矛盾消解 | SUPERSEDES 边 + valid_to 失效 + `lookup_as_of` 双时态查询 |
| 弃答 | 证据分+语境双闸门，阈值走配置标定 |
| 时序推理 | `parse_relative` 以 question_date 为锚解析相对时间词 |
| 事件排序 | NEXT 链 + `order_events` 全局排序，答案按时间序组合 |
| 证据命中 | `remember_turn` 结构化摄入，dia_id/session_id 落事件属性 |
| 多跳推理 | M6 加权扩散（因果/组成/共现通道）+ M8 多轮思考 |

## 四、评测结果记录

### 4.1 LoCoMo 全量（1986 题）

| 管线 | judge | F1 | recall@10 | abstain_acc（cat5 对抗） |
|---|---|---|---|---|
| 离线基线（规则提取+基线答题） | — | 0.019 | 0.310 | 0.000 |
| LLM v1（LLM 提取+答题+判分） | 0.103 | 0.051 | 0.279 | **0.904** |

v1 分 category（judge）：cat1=0.106 / cat2=0.003 / cat3=0.073 / cat4=0.153 / cat5=0.085。

**首版结论**：对抗题弃答（0.904）验证有效；但可答题过度弃答（77~94% 被判 NO INFORMATION）+ 检索召回不足（recall@10 仅 0.28）是两大瓶颈。与公开系统（judge 0.5~0.7 量级）差距明显，进入小样本迭代。

### 4.2 LongMemEval-S

全量跑因耗时（预计 5~7 小时）按决策暂停于 289/500，LLM 缓存（4500+ 条）保留，可随时断点续跑。

### 4.3 小样本迭代与当前最优管线

固定小样本（LoCoMo cat1~5 各 10 题共 50 题 / LME multi-session 30 题）逐轮 A/B 后的当前最优管线：rule 摄入 + 实体档案 + 蒸馏词典 + 查询扩展 + 证据内容词终排 + NEXT±1 证据打包 + think + k_pool 候选池。

| 基准 | recall@10 | judge | 备注 |
|---|---|---|---|
| LoCoMo sample50（固定 50 题） | 0.500 | 0.500 | 起点 0.271/0.220；recall 0.542→0.500 微降、judge 0.440→0.500 |
| LoCoMo 全量 v3（1986 题） | 0.654（cat2） | 0.375 | 全量 LLM 管线 |
| LongMemEval 全量 500 | 0.672 | 0.398 | 修复前分型见 §4.5 |
| LongMemEval 前 100 | 0.820 | 0.590 | single-session 0.757 / multi-session 0.200 |

已否证并回退的方向：证据摘要整合（digest，纯摘要/双通道/仅供定位三版全负，功能已干净移除）、IRCoT 对聚合题（检索侧有效但答题侧零翻转，默认关）、条件归一、WordNet/gap 大词典默认灌库。

### 4.4 两阶段聚合作答（降本组合 A/B）

聚合类问题（how many/total/所有，模式匹配触发，非聚合走单阶段零两阶段开销）：
k_pool 候选池（~50 条）→ 本地预过滤（池内 BM25-lite，零 LLM，保留 N=20）→
批量提取（5 条/次编号 [E#] 输入、逐条输出事实/NONE，保留思考）→ 事实列表聚合作答。

LME 14 道聚合题实测：judge 3/14 vs 逐条基线 0/14（3 题 0→1、零退化）；answer 侧调用
4.8 次/题 vs 逐条 16.2 次/题（约 1/3.4），含判分 6.6 次/题；同参数第二遍缓存重放 0 新调用。
瓶颈仍在阶段一提取召回（平均 3.2 条事实/题），未达转正线，`--answer-mode aggregate` 默认关。

### 4.5 全量评测失败点分析与修复（失败分析驱动，A/B 验证）

**失败点一：LoCoMo cat2 时序题（v3 judge 0.072，recall 0.654）**

- 逐题分类（12 题抽样，judge=0 且证据命中）：12/12 时间锚定错——答案统一锚到
  2023-11 月，金标均为 5~7 月。
- 根因链（双根因）：① `parse_session_date` 不识别 LoCoMo 月名日期格式
  （"1:56 pm on 8 May, 2023"）：数字扫描把时分 1:56 的 1/56 误判为月/日 → 解析失败 →
  全部会话落入合成时间戳（kBase=1700000000 ≈ 2023-11-14 起按会话序递增）→ 证据召回
  正确但喂给 LLM 的日期标签全错。② think 证据并入（前置）带时近偏置（rerank γ·decay
  90 天半衰项），词面精确命中的金标被顶到队尾（实测 "charity race" 金标 D2:1 排第 9，
  top-3 全是近期客套轮，LLM 据 top 证据答错）。
- 消融归因：仅终排修复（日期仍错）A/B = 0/12 → 日期修复必要；v3 证据 top-3 全无关
  而金标在 top-10 → 终排修复必要（修后 top-3 即金标轮）。
- 修复清单：月名日期解析（词边界匹配，缩写/全名均可，数字格式回归不变）+ 证据内容词
  BM25-lite 终排（recall 大候选池不提前截断，终排后才截 top-k；stable 排序，无内容
  信号不扰动原排序）。
- A/B（12 题抽样）：judge 0/12 → 11/12，recall@10 = 1.0，F1 0.125 → 0.518。

**失败点二：LME single-session-preference（judge 0/30，recall 0.233，误弃答 23/30）**

- 逐题分类（30 题全量）：23/30 误弃答 + 7/30 答非所问，30/30 金标会话不在 top-10。
- 根因链：实体通道第一人称映射按 INVOLVES 度数盲选主说话人——assistant（258）高于
  user（250）错选助手实体 → 检索池错位（金标 INVOLVES user，不在 assistant 池）→
  通道返回弱证据并弃答，遮蔽标准管道的正确召回。反直觉点：金标轮与问题有词面重叠
  （"video editing" 全 haystack 仅出现于金标 2 轮），并非"偏好零词面重叠"假设。
- 消融归因：图快照离线单题验证——实体通道关闭时标准管道 recall=1.0；角色感知修复后
  通道开启 recall 同为 1.0 且金标 top-1。
- 修复清单：角色感知第一人称（优先 user 角色名、排除 assistant 角色名）+ 通道弃权
  回退（通道证据分低于阈值时回退标准管道）+ 弃答门控对内容词精确命中豁免（哈希语境
  余弦弱信号不得否决词面精确命中）。
- A/B（30 题全量）：judge 0/30 → 8/30，recall 0.233 → 0.633，误弃答 23/30 → 14/30。

**sample50 回归影响**：judge 0.440 → 0.500（净升），recall 0.542 → 0.500（微降）；
cat5 对抗题弃答率 0.8 → 0.6（门控豁免的代价，judge 未受损）。

**遗留**：偏好题残余失败以"召回但个性化不充分"为主（judge 判用户偏好体现不足），
写入侧偏好槽位直查为候选方向；v3 / LME 500 全量数字为修复前口径，待重跑刷新。

## 六、优化方法论

1. **可观测性先行**：逐题 dump（NDJSON：问题/回答/弃答/证据 top3/证据分/judge），失败分析不再打 API。
2. **失败四分类**：检索未召回 / 召回但误弃答 / 召回答了但答错 / judge 误判——不同失败不同修法，先定量再动手。
3. **极小样本快速迭代**：固定小样本集（cat1~5 各抽 10 题共 50 题），每轮只验证一个改动，有效才放大；阈值类参数用小样本扫描标定（验证集口径，报告注明）。
4. **Token 经济**：LLM 调用全量磁盘缓存（prompt+model hash），调优迭代只重打改了 prompt 的环节；提取结果缓存复用，answer/judge 迭代零提取成本。
5. **不套答案**：所有优化必须是通用机制（词典从语料词汇蒸馏、阈值从验证集标定），禁止读取/利用参考答案。

## 七、语义增强方案（词典蒸馏）

### 7.1 问题定位

哈希 embedding 无语义：问题词与对话词重合主要靠人名，内容词重合度低（问题问 "activity"，对话写 "hiking"）。实测语料词汇：对话 5619 内容词 / 问题 1963 内容词（`bench/data/vocab_freq.json`）。

### 7.2 双通道方案

语义知识按设计哲学分走两个通道，不可混用：

- **图通道（图层）**：LLM 批量蒸馏同义/反义/上下位关系 → 同义灌 `RELATED{相似}` 边 + M3 别名归一表；反义灌 `RELATED{对立}` 边（**反义必须走图不能走向量**——向量空间中反义词距离天然很近，不单独切出会被扩散当作强联想）；上下位/因果选择性灌组成/因果边。
- **向量通道（向量层）**：候选①语料自训练 skip-gram（纯 C++，零 API 成本，领域贴合，OOV 回退哈希）；候选②外部 embedding API（DeepSeek 无 embedding 接口，需另接）。

### 7.3 蒸馏执行与验证

- 范围：5619+1963 真实用词，按 ~50 词/批调 DeepSeek，约 100~150 次调用，磁盘缓存一次投入永久复用。
- 验证：固定 50 题小样本 A/B（灌词典前后 recall@10 / judge / 误弃答率对比），有效才全量。

### 7.4 词典三源落地状态（已解决）

| 源 | 产物 | 规模 | 说明 |
|---|---|---|---|
| LLM 蒸馏 | `lexicon.json` + `lexicon_gap.json` | 2910+770 词 | 三分流 schema（syn_strong/syn_near/antonyms），面向本语料词表，**默认管线** |
| 英文 WordNet 3.1 | `lexicon_wordnet.json` | 206,670 词条 | npm wordnet-db 离线转换；sample50 负收益，保留待用 |
| 中文词林 | `lexicon_zh.json` | 77,305 词条（strong 78,707/near 39,593/antonym 21,236 对） | funNLP 同义词词林（9,995 同义组/3,445 近义组）+ 反义词库（18,305 对），`convert_zh.py` 离线转换 |
| 中文箭头对同义词典 | `lexicon_zh2.json` | 20,305 词条 | funNLP `input/同义词.txt`（GBK，`word→syn` 箭头对），`organize_dicts.py` 整理后经 `convert_zh.py` 转换 |
| 高频 LLM 蒸馏 | `lexicon_hf.json` | 687,435 词条（top_n=800000） | 全库合并词频分块增量蒸馏，断点续跑（`--build-lexicon bench/data/vocab_hf.json --lexicon-out bench/data/lexicon_hf.json`），三分流 schema 同上 |

关键机制教训：
- **分流**（M3 原义）：synset 内部真同义→别名归并；跨组近义→保留双节点 REL_SIMILAR 边；反义→REL_OPPOSITE（系数 0.5 最低档）。
- **canonical**：同义组以组内首词为全组标准词，避免两两互指归一链/环。
- **内置标准词保护**：`builtin_standards_`（失眠/压力等）不可被外部词典改写，否则发生 失眠→辗转反侧 这类归一事故。
- **CJK 词法种子**：中文无分词器，走 M1 词典词 + 子串匹配事件原文 + 同义组扩展。
- 中文验证用例（test_bench::test_chinese_lexicon）："失眠" 命中 "睡不着" 事件（归一）、"开心" 不把 "悲伤" 事件顶到前面（对立抑制）、灌库幂等。

## 八、实体记忆专门结构（实体档案）

### 8.1 问题定位

全量 dump 分析发现：人名锚点"工作正常但喧宾夺主"——查询 "When did Melanie paint a sunrise?" 检索回的全是提到 Melanie 的轮次（session 6~19），真正的画画事件（session 1）被挤出 top-k。检索命中的最早 session 比 gold 平均早 7 个（靠前会话人名密集，实体锚点吸走扩散能量）。

根因：实体在实现里只是普通图节点，**实体的组织作用没有结构化**——实体应该既是记忆的"档案夹"（这个人的事实都归拢在它名下），又是检索的"过滤器"（先圈定人的范围，再按内容排序），而不是和内容关键词抢能量的扩散源。

### 8.2 实体档案（Entity Profile）四层结构

| 层 | 内容 | 现状 |
|---|---|---|
| 身份层 | uid / 标准名 / 别名 / 强标识符 | 已有（M2 EntityCard） |
| 属性槽位层 | (slot, value, valid_from/to, source_event) 四元组：居住地、职业、家庭成员、偏好、拥有物；冲突走 SUPERSEDES，当前值与历史都可查 | **已落地**（`put_slot`/`slot_as_of` 双时态，`--entity-profile on` 启用） |
| 关系层 | 实体间类型化边：家人/朋友/同事/拥有（从 "my son Jake" 类表述蒸馏）；EXPERIENCED_TOGETHER 已有 | 部分落地 |
| 时间线层 | INVOLVES + NEXT 链的实体视图："X 最近经历了什么" | 待建（零件都有） |

### 8.3 检索角色修正

- **实体 + 内容词混合查询**（LoCoMo 主流题型）：实体做候选池圈定（lookup entities=X），内容词在池内驱动排序——两阶段而非能量竞争。
- **纯实体查询**：直查档案槽位/时间线，不走扩散。
- **防能量垄断**：实体类种子总权重封顶，或实体节点扩散限 1 跳透传。

落地状态：两阶段检索"实体圈池、内容排序"已实现并进入默认管线（`--entity-profile on`），
是 sample50 0.500/0.500 的组成之一。

### 8.4 对基准能力的收益

- "Where does Caroline live?" → 槽位直查（信息抽取/知识更新题）
- "What did X do recently?" → 时间线尾端（时序题）
- 人名+内容混合题 → 实体过滤 + 内容排序（单跳/多跳主体）
- 偏好题 → 偏好槽位的当前值（SUPERSEDES 保证取最新）
