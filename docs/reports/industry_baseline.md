# 行业参考记忆基线报告（Mem0/Zep 式 RAG 的零-LLM 形态）

**分支**：`dev-2.0`｜ **性质**：纯脚本参照臂（`bench/scripts/ref_rag_baseline.py`），C++ 零改动
**问题**：AME 四档在同题同指标下，与"行业默认直觉配置"的 RAG 记忆基线谁强？差多少？差在模型还是管线？

---

## 1. 对照表（LoCoMo sample50 / conv-26 419 轮 / 覆盖率 = |gold∩top-10|/|gold| 宏平均，n=48）

|---|---|---|---|---|
| **AME bm25** | 0.464 | 25/48 | 无 | 引擎词面档（冻结配置） |
| **AME cheap** | 0.557 | 29/48 | 无 | 特征重排档（冻结配置） |

## 2. 判读（预注册）

1. **"AME 零-LLM 记忆层 ≥ 行业标准 RAG 参照"——成立，且是大胜**：AME cheap 0.557
   vs dense-turn 0.347 = **+0.210（相对 +60.5%）**；vs 更强词面参照 bm25-turn
   0.479 也高出 +0.078。手写 BM25 0.479 ≈ AME bm25 0.464（+0.015，词面检索
    parity 成立，差距全部来自 cheap 的特征重排层）。
2. **svec 档 vs dense-turn 同模型（bge-small int8）：0.578 vs 0.347 = +0.231**——
   同一份向量，增益全部来自 AME 管线（融合特征/图扩散/实体通道/学习重排），
   **不是模型红利**。
3. **模型规模不是瓶颈**：bge-large（337MB int8，14× 参数）dense-turn 也只有
   0.469，仍低于 AME cheap 0.557（零 LLM、34MB 级）。给"换大模型"路线的一记
   反证：同样裸检索形态，加大模型 +0.122；加 AME 管线 +0.231（从 0.347 到 0.578）。
4. **dense-window 的 0.773 是与 AME 不可比的粒度假象**（§3）——但它作为
   行业配置样本有独立价值：在本语料规模（419 短轮、平均每轮 ~52 token）下，
   "500-token 滑窗"把 ~13.5 轮糊成一个块，31 块取 10 = 检索 32% 语料，
   覆盖率被份额而非精度抬高。

## 3. 窗切块量化解剖（dense-window vs dense-turn）

- **粒度对照实验（关键控制）**：dense-turn 取 k=130（= 10 窗 × 平均 13.5 轮/窗
  的等语料份额）→ **0.906**，反超窗臂严格口径 0.773 达 +0.133。结论：在等
  top-k 份额下，**窗切块相对轮切块是净伤害**（邻近轮语义稀释向量 + 金标轮
  跨窗边界被切碎）；窗臂表面 0.773 > AME llm 0.672 完全由"top-10/31 块"的
  高份额造成，不构成本领比较。
- **切块策略影响量化（同 bge-small、同 k=10 的表观口径）**：0.347（turn）→
  0.773（window）看似 +0.426；等份额校正后 0.906（turn）→ 0.773（window）
  = **-0.133**。行业"大窗"直觉在小粒度会话语料上不成立；Mem0/Zep 实际以
  轮/句级语义块为主，dense-turn 才是它们的可比形态。

## 4. 成本账

- 参照臂一次推理：small 三臂合计 ~15 s（轮/查询嵌入大部分命中 svec 引擎
  运行留下的缓存）；large 臂 ~40 s（419 轮 × 335M 参数 int8）。复跑全部缓存
  命中 <1 s（`bench/models/cache`，文本 sha1）。
- 体积参照：bge-small int8 34MB（AME svec 档同模型）；bge-large int8 337MB
  （APK 量级参照）——0.469 的上限参照花 10 倍体积仍不及 AME cheap，见 §2.3。

## 5. 蓝方自检

1. **窗臂金标命中口径（预注册要求取严）**：主口径 = **top-10 窗中存在完整覆盖
   金标轮的窗**（turn token span ⊆ window span）——比 AME"轮入选 top-k"更严
   （AME 不要求整轮未被切碎）。宽松交叠口径（0.811）并列披露；严格口径下窗臂
   仍高，证明其高分来自粒度而非口径放宽。
2. **粒度对照完整性**：dense-turn@k=130 用与窗臂完全相同的嵌入与查询，仅改
   取 top-k 数，份额换算按实测窗-轮覆盖数（~13.5 轮/窗），无调参。
3. **查询/索引一致性**：查询侧 = bge 官方检索指令 + 均值池化 + L2（kind 'q'，
   与 AME svec 档同）；索引侧 = 无指令（kind 'p'/'w'）；BM25 查询与索引共用同
   一切词器（AME content_words 口径：ASCII 小写 len≥3），无分析器不对称。
4. **嵌入缓存键**：sha1(模型目录名-文件名|kind|文本)。实现中发现并修复一个
   真实碰撞：small/large 的 onnx 同名（model_quantized），旧键会让 large 臂
   吃到 small 的向量——键已加模型目录名，修复后 large 臂数字有效。
5. **公平性**：参照臂零调参（官方指令/默认池化、k1=1.2 b=0.75、500/50 窗、
   top-10）；AME 侧为冻结配置带内取值；题目与金标取自 AME judge 臂 dump
  （同一份数据，无重标注）；AME 侧 entity-pass/guard 横切在参照臂无对应物——
   这是"系统 vs 裸检索"的对比意图本身，非偏置。
6. **限制披露**：参照臂无跨会话身份解析/别名（AME M2/M3 模块的对应物），
   人物改述题（LoCoMo cat3/cat4 高发）上参照臂吃亏是设计使然；"行业默认"
   不唯一，本报告数字只对"轮/窗切块 + bge + 余弦/BM25 top-10"这一具体
   形态负责。
