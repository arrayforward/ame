# 句级语义的真实上限：oracle 测量（三实验）

> 前置：LLM 重排 spike（`llm_rerank_spike.md`）因结构性缺陷（33/50 题被实体
> 通道截走、到达者金标全在 top-20 窗外）测错了问题，用户裁决"还不到终局"。
> 本报告测真问题：**任何"句级相关性机制"的理论上限是多少？** 三个 oracle
> 实验全部用 LLM 当完美裁决器（上限语义：不计成本、假设产品机制达到 oracle
> 选中率），LLM 调用走 bench/cache 磁盘缓存，全部命令可复跑。
>
> 口径：coverage = |gold ∩ evidence_dia_ids| / |gold|，有金标题均值（n=48），
> 与历轮 A/B 完全一致；graph 后端 / sample50 / extractor rule / k=10 / k_pool=60。

## 0. 结论速览（三个上限数字）

| 实验 | 上限数字 | 一句话 |
|---|---|---|
| **E1 B 类池级重排** | **可回收 4/6**（金标在池 4/6，**在池者 LLM 选中率 4/4**） | 池级语义排序可行——B 类不是标注/噪声域，是窗口域 |
| **E2 A 类查询扩展** | **新进池 2/5**（严格）/ 池可达 3/5（含 q105 原池在池） | 方向对 2/5 成立、2/5 连扩展都跨不过（灰区偏负），代价是池噪声近翻倍 |
| **E3 实体通道审计** | **净贡献 ≈ 0**（覆盖 Δ+0.005 噪声内；judge 2/33 vs 反事实 4/33） | 不是资产也不是净害，但它是**墙**：把 E1 机制对 2/4 个可回收 B 题（q10/q155）锁在门外 |

**天花板：覆盖率 0.464（词级 plateau）→ 理论 ≈ 0.59**（B 类全回收 +4/48、
A 类全回收 +3/48；锚定本轮实测 C0=0.443，即 0.443+0.146=0.589）。
句级语义方向的理论上限约 **+0.13**（对 plateau），远超词级六轮的 +0.016——
**立项依据成立，且 E1 证明了主机制（池级语义打分）在池内 100% 可达。**

## 1. E1：B 类整池 LLM 重排天花板

**方法**：对 taxonomy B 类 6 题（金标在 lmem 口径池内但 rank>10），把标准管道
整池 60 条（dia_id + 首 200 字，融合序）一次性给 LLM，指令"选出对回答问题
最有用的前 10 条"，看金标是否入选 LLM 的 top-10。

**Prompt（全文）**：

```
你是检索重排器。给定一个问题（题号 <qid>）和 60 条候选证据（编号 E1..E60，
方括号内为来源标记，文本可能被截断）。
任务：选出对回答该问题最有用的前 10 条证据，按相关度从高到低给出编号。

问题: <question>

E1 [D3:13] <首 200 字>
...
E60 [..] <首 200 字>

只输出编号列表（形如: E3 E1 E7），恰好 10 个或少于 10 个（如果不够相关），
按相关度排序；若都不相关只输出 NONE。不要输出任何解释。
```

**逐题结果**（`bench/runs/oracle_ceiling/e1.ndjson`）：

| qid | 金标 | 金标 BM25 序 | 金标在池 | LLM top-10 入选 |
|---|---|---|---|---|
| q10 | D3:13 | 20 | ✓ | **✓** |
| q101 | D5:8 | 27 | ✓ | **✓** |
| q154 | D2:12 | 20 | ✓ | **✓** |
| q155 | D2:12 | 21 | ✓ | **✓** |
| q34 | D3:3, D9:2 | — | ✗（graph 池无） | ✗（oracle 也救不了） |
| q50 | D12:1 | — | ✗（graph 池无） | ✗（oracle 也救不了） |

**判读（预注册）**：进 ≥4/6 → 池级语义排序可行；≤2/6 → B 类是标注/噪声域。
**实测 4/6，且在池者 4/4 全选**——B 类可回收上限 = 4/6 = +4/48 = **+0.083**。
q34/q50 在 graph 口径金标根本不在 k_pool=60 池内（lmem 口径在），它们是
召回域问题（见 E2 的天花板逻辑），不归排序机制管。

**重要修正**：spike 的"N=20 窗口"漏掉的正是这 4 题——金标 BM25 序 20/21/27/20，
全部卡在 10~20/27 位；整池打分（或 N≥30 的窗口）即可触及。

## 2. E2：A 类 LLM 查询扩展天花板

**方法**：对 A 类 5 题（金标不在池），LLM 生成 3 条改写检索查询
（paraphrase/expansion），逐查询跑**同一词面召回**（同 SeedQuery 参数，
k_pool=60），看金标是否因此进池；同时计数进池的非金标噪声。

**Prompt（全文）**：

```
给定问题（题号 <qid>），生成 3 条改写检索查询（paraphrase / expansion，用于
关键词式召回，覆盖问题的不同语义侧面，可以换近义词、具体化或补充上下文）。
问题: <question>

只输出 3 行，格式：
Q1: <查询>
Q2: <查询>
Q3: <查询>
不要输出其他内容。
```

**逐题结果**（`bench/runs/oracle_ceiling/e2.ndjson`）：

| qid | 金标 | 原池金标 | 扩展新进池 | 命中查询 | 新噪声（非金标） | 并池 |
|---|---|---|---|---|---|---|
| q18 | D6:16, D4:6, D8:32（3 条） | 0 | **3 条全进** | 3/3 | 45 | 108 |
| q64 | D15:28 | 0 | **进** | 2/3 | 50 | 111 |
| q105 | D7:13 | **1（原池在，BM25 59）** | — | 1/3 | 56 | 116 |
| q3 | D2:8 | 0 | ✗ | 0/3 | 57 | 117 |
| q156 | D2:14 | 0 | ✗ | 0/3 | 63 | 123 |

**判读（预注册）**：≥3/5 进池 → 方向成立；≤1/5 → 跨不过。
**实测：严格口径（扩展因此新进）2/5；宽松口径（池可达，含 q105 原池在）3/5**
——踩线灰区。结构上可分：q18/q64 的鸿沟是**词汇层**（camping / Vivaldi·
Four Seasons·Baroque——扩展词即过桥，3/3 与 2/3 查询命中）；q3/q156 连
LLM 改写都跨不过（生成查询的召回池仍无金标），属于更深的鸿沟（需真向量
或推理链）。**代价量化：每题引入 45~63 条非金标新进池（池近乎翻倍）**——
扩展若进产品形态必须配套更强的排序门。
**A 类可回收上限 = 3/5 = +3/48 = +0.062**（q18/q64 靠扩展进池 + q105 靠
池内排序；q105 的归属见 §4 去重）。

## 3. E3：实体档案通道净贡献审计

**方法**：三次 CLI 运行（graph/sample50/judge llm，judge 同缓存条件）：
on = 生产路径（实体通道开）；attr = on + `--llm-rerank 20` 仅取逐题归因日志
（哪些题被实体通道提前返回）；off = `--entity-profile off` 反事实
（标准管道假设表现）。截走判定用合并版二进制的诊断日志
（`[llm-rerank] <qid>: 实体档案通道提前返回，未重排`），非猜测。

**结果**：

- **截走 33/50 题**（66%——与 spike 一致）。
- 截走题 coverage：通道受益 1 题（q160：on 1.0 vs off 0.0）/ 通道受损 1 题
  （q107：on 0.0 vs off 1.0）/ 持平 31 题；全样本 on=0.443 vs off=0.448，
  Δ=+0.005 在噪声带内——**覆盖率维度净贡献 ≈ 0**。
- 截走题 judge 答对：on（通道实际作答）**2/33**（q12、q46）vs off（标准管道
  反事实）**4/33**（q100、q108、q12、q158）——judge 维度通道略负（-2 题），
  但它答的题多半本来也答不对（33 题里 31 题覆盖持平且 judge=0）。
- q104 被截走但通道处理正确（金标 D7:11 命中）——graph 口径下 q104 不是
  近失题（spike 的"q104 型"结论修正为 lmem 口径现象）。

**净贡献结论：它不是资产（judge 2/33）、也不是净害（覆盖噪声内），但它是
墙**——66% 的题绕过了 BM25 终排与任何未来的池级语义打分；特别是 E1 证明
可回收的 4 个 B 题里 **q10/q155 被它截走**（它的池内排序同样把金标排在
top-10 外，且池内无 LLM 重排）。

## 4. 天花板总结

锚定：本轮实测 C0=0.443（与记录基线 0.448 同噪声带）；词级 plateau 0.464。

| 来源 | 可回收 | 覆盖率增量 | 依赖 |
|---|---|---|---|
| B 类池级重排（E1） | 4/6 | +4/48 = **+0.083** | q10/q155 需实体通道放行（改造或池内重排） |
| A 类查询扩展（E2 严格） | 2/5 | +2/48 = +0.042 | 池噪声近翻倍，需排序门 |
| A 类 q105（E2 池检查） | 1/5 | +1/48 = +0.021 | 仅池级排序即可（金标原池在，BM25 59） |
| A 类合计 | 3/5 | **+3/48 = +0.062** | |
| **合计天花板** | | **+0.146** | |
| **0.464 → 理论上限** | | **≈ 0.589**（C0 口径 0.443+0.146） | |

说明：这是**上限**（oracle 假设产品机制达到 LLM 选中率）；E1 在池选中率 4/4
支持该假设对"池级打分"近似成立，E2 回收的金标进的是翻倍噪声池，实际选中率
会低于 1.0——乐观偏差方向已在蓝方 §6 量化声明。q34/q50（B 类 2 题）、
q3/q156（A 类 2 题）四题**不在任何句级机制的上限内**（金标不在池且扩展
也够不到），它们划定了句级范式的真实边界：≈4/48 ≈ 0.08 永久不可达。

## 5. 机制设计建议（按上限数据排优先级）

1. **池级语义打分（预期 +0.083，最高优先）**。E1 已证明：金标在池时
   LLM 整池 top-10 选中率 4/4。产品形态两条路：(a) 全池 LLM 打分——
   成本 50 题 × 60 池 ≈ 300k tokens/轮，贵但判决实验说明收益上限够格做
   蒸馏；(b) 蒸馏小模型/异步打分——先用全池 LLM 打分造监督数据
   （本报告的 e1.ndjson 即首批标注），这正是 spike 判决线"≥+0.05 触发
   便宜近似设计"的触发条件（oracle 版 +0.083 ≥ +0.05）。
   工程前提 = 第 2 项。
2. **实体通道改造（解锁 +0.042 中属于 q10/q155 的部分，纯工程零 LLM）**。
   不是拆通道（E3：覆盖净贡献 0、q104/q160 靠它），而是**把池级打分也挂进
   实体通道的候选排序**（它的 lookup 池同样 60+ 条、同样 BM25 终排），或
   低置信时放行标准管道。收益 = 让 E1 的 4/4 覆盖到被截走的题。
3. **LLM 查询扩展（预期 +0.042，最低优先）**。2/5 成功率、池噪声近翻倍、
   每题 2 次 LLM 调用；只在第 1 项落地后作为**扩池的增量**考虑
   （先扩展进池、再由池级打分把关噪声）。q3/q156 的失败提示该机制天花板
   低，不值得单独立项。

## 6. 蓝方自检逐条

1. **LLM"相关"≠金标口径的偏差方向（双向计数）**：
   - *LLM 认为相关但金标没有（false positive）*：E1 共 60 个 LLM 选中位
     （6 题 × 10），其中非金标 56 个——但这是 top-10 的正常构成，coverage
     口径只问金标在不在，不产生假阳性损失；E2 的对应物是**进池非金标噪声
     45~63 条/题**（已量化，进报告 §2）。
   - *金标在但 LLM 不选（false negative）*：E1 在池金标 4 条，落选 0 条
     （0/4）；spike 窗口版 r2 的 13 置顶里金标落选若干（窗口所致，非本实验）。
   - 偏差方向结论：oracle 在"池内选金标"上无实测偏差，上限数字不因该偏差
     膨胀。
2. **E2 假阳性**：每题扩展并池新增 45~63 条非金标（q156 最多 63，池 60→123）。
   若扩展与池级打分组合，排序门面对双倍池——这是 E2 收益 +0.042 的隐性
   成本，已在优先级第 3 条降级处理。
3. **E2 召回口径**：扩展查询未继承原题时间过滤（parse_relative 锚点），
   可能引入时间窗外事件——只影响"进池"判定不影响本实验结论（金标判定
   用 dia_id 集合）；产品上扩展查询的时间处理需单独设计。
4. **E3 反事实口径说明**：off 运行 = 同摄入同 recall 仅关实体通道，是
   "标准管道假设表现"而非真实历史路径（这些题生产上从未走过标准管道）；
   uid 噪声使单题对比有 ±1 题翻转风险（q32 型），故净贡献结论锚定
   "33 题聚合 + 噪声带"而非单题。judge 维度 n=33 功效有限（2 vs 4），
   只作方向参考。
5. **缓存防污染**：全部 LLM 调用经 DeepSeekClient，缓存键 = FNV-1a
   （模型+消息+选项）；prompt 含题 id + 池内容（dia_id+文本）/生成查询，
   与历史 answer/judge 缓存零碰撞。实测 e1/e2 全 miss（全新 prompt），
   e3_off 的 judge 与 e3_on 同 prompt 命中 13/50。
6. **oracle 上限的乐观性**：假设产品机制 = LLM 选中率。对 E1（在池 4/4）
   近似成立；对 E2 回收（噪声翻倍池）系统性偏乐观——0.589 应读作
   "≈0.55~0.59 区间上限"。词级六轮纪律（预注册线、噪声带 ±0.005）沿用。

## 9. 机制 1 实施与验收：实体档案通道低置信放行（--entity-pass-threshold）

> 判决依据：E3（通道是墙，截走 33/50 净贡献≈0）+ E1（q10/q155 可回收但被锁）。

**实现**（`bench/src/ingest_answer.cpp` answer() 步骤0 + `bench.h` +
`bench/cli/main.cpp`）：

- 置信信号 = 通道裁决榜首内容分（`answer_entity_channel` 的 `ar.score`，
  槽位直查恒 1.0——天然永远高置信，不受影响）。阈值默认 **-1 = 关闭 =
  现状**（不传开关逐行不变）；`--entity-pass-threshold X` 开启。
- 低置信（score < X）→ 不整通道返回；其候选（top-k 证据 uid）**按 uid 去重
  并入标准管道候选池**（recall 池构建后、think 并入前；ScoredEvent 分数置 0，
  终排只看内容词 BM25），随后走标准流程（think 并入 → BM25 终排 → 截 top-k）。
- 高置信 → 下方原有整通道返回代码逐行不动。
- 合并实现教训：先完整构建持有容器再统一取指针——边 push 边取 `&back()`
  在 realloc 时悬空（首版 segfault 实测暴露，单测捕获后修复）。
- 单测 `test_entity_pass_through` 3 组：默认关 = 整通道返回（证据双标记
  D1:1+S:s1 逐字段断言）；阈值 0.5 = 放行（通道候选不丢 + 标准管道取证生效）；
  阈值 0（0.16 ≥ 0）= 仍整通道返回。

**A/B 验收**（graph/sample50，同 off 配置，零 LLM）：

| 组 | 覆盖率（n=48） | any-hit | Δ vs off 复跑 0.443 | 丢失 |
|---|---|---|---|---|
| off 复跑 | 0.443 | 24/48 | — | — |
| m1 = --entity-pass-threshold 0.5 | **0.464** | 25/48 | **+0.021** | **0 题** |

- 阈值 0.5 下 **33 题全部放行**（被截走题通道分实测最高 0.471 < 0.5），
  即该样本上 0.5 ≈ "全放行但候选并入"；17 题本就走标准管道不受影响。
- **硬判据核验**：q10/q155 金标在放行后**进入合并池**（对下游可见，
  m12 日志 `金标∈候选=True` 两题均成立）；但仅凭机制 1（BM25 终排不变）
  金标位于 BM25 20/21 位进不了 top-10——"最终证据见金标"需机制 2 兑现
  （见 §10，两题最终 top-1 入选）。
- 独立收益：q107 救回（0→1.0——E3 里被通道压掉的题，放行后标准管道捞起）；
  q104 -type 无伤害（金标 D7:11 从第 2 位移到第 7 位仍在 top-10）。
- **判决：机制 1 成立**（零回归 + 解锁 + 独立 +0.021；作为机制 2 的
  工程前置生效）。

## 10. 机制 2 实施与验收：全池 LLM 语义打分（--llm-rerank-all）

> 判决依据：E1 oracle（池级打分可回收 B 类 4/4=+0.083，在池选中率 4/4）。

**实现**：`--llm-rerank-all`（裸开关，默认关）把重排窗口从 `--llm-rerank N`
的 top-N 扩为**全池 evs.size()**（含机制 1 并入的通道候选）；其余与 spike
通道完全一致（终排后截 top-k 前一次 LLM 调用、编号序前 k 置顶、失败/无有效
编号优雅降级 BM25 原序、prompt 含题 id+全池 dia_id+首 200 字天然防缓存污染）。
两开关独立，可叠加（全池优先）。`--llm-rerank-all` 初版误按键值对解析吃掉
下一个参数（`--dump` 被吞），已改裸开关并复跑（教训记入蓝方）。

**A/B 验收**（graph/sample50；off 复跑 0.443）：

| 组 | 覆盖率（n=48） | any-hit | Δ | B 类 4 题金标进 top-k | judge 均值 | api_calls |
|---|---|---|---|---|---|---|
| m2 = --llm-rerank-all | **0.526** | 29/48 | **+0.083** | 2/4（q101✓q154✓；q10/q155 被通道截走未触达） | 未测 | 17 |
| m12 = 机制1+2 | **0.604** | 34/48 | **+0.161** | **4/4**（q10 位1 / q101 位2 / q154 位1 / q155 位1） | **0.440** | 71（缓存命中 29） |

- **预注册硬判据全部通过**：覆盖率 ≥0.52（实测 0.526 / 0.604）✓；
  B 类 ≥3/4（实测 4/4，选中序位 1/2/1/1）✓；judge 跟随测：基线路径 0.080 →
  组合 0.440（答案质量 5.5×，n=50 同题聚合）✓。
- **对 oracle 的验证**：m2 单独 Δ=+0.083 与 E1 oracle 预测（+0.083）**精确
  一致**——oracle 的"在池选中率"假设被产品形态直接复现，偏差方向声明
  （§6.6）的乐观担忧在 B 类上不成立。组合 +0.161 超出天花板估计 +0.146，
  因为实际救回 11 题（q10/q101/q103/q105/q13/q154/q155/q19/q24/q32/q153），
  含 taxonomy 目标外的 C 类改述题（q13/q32/q103 型）——天花板是按 taxonomy
  目标算的保守下界，实际机制惠及面更宽。
- **唯一回退**：q100（金标 D4:15 在 off 为 top-1，LLM 全池重排后被挤出去，
  1.0→0.0）。11 救 1 失的净账仍显著为正；此为 LLM 重排的固有假阳性风险
  （蓝方 §11.4），q100 型（词面精确命中且 LLM 判断"问题需要推理而非直接
  证据"）是已知失败模式。
- 全池触发统计（m12）：50/50 题全部触发（42 置顶 + 8 个 NONE 正确降级，
  8 题金标本不在池——与 E1/E2 的池外题集合一致）；0 题"候选≤1"。
- **成本实测**（便宜近似设计的输入数据）：全池 prompt ≈ 64~67 条 ×
  (dia_id + 200 字) ≈ 13k 字符 ≈ **3.5~4k tokens/次**；单轮评测
  50 次重排 + 50 次 judge = 100 次调用（本组热缓存后实扣 71）。对比
  spike 窗口版（17 次/轮），全池版每轮多 ~33 次调用、单次 token ×3——
  **蒸馏/缓存形态（按 e1.ndjson 同款标注造监督数据）是下一步的明确输入**。

**判决：机制 2 成立**，且 E1 oracle 的立项判断被实测复现（+0.083 分毫不差）。

## 11. 蓝方自检（机制 1/2 追加）

1. **放行后池子去重**：通道候选按 uid 对 recall 池去重（`present` 集合），
   重叠不重复占位；每题并入 ≤10 条，池 60→最多 70（实测 64~67，说明
   通道候选与 recall 池重叠约 3~6 条/题）。合并项 ScoredEvent 分数置 0：

   tokens/次（§10 成本行）；60×200 字截断是 spike 既有设计，超长轮尾部
   信息不可见的风险同 spike（本样本未观测到因此的误判）。
3. **降级路径**：8/50 题 NONE 降级全部是金标不在池的正确判断（与 E1/E2
   池外集合一致），降级后 = BM25 原序，无题因此比 off 更差（m2/m12
   "丢失"集合 = 置顶题内的 q100 一单）。

## 13. 任务 A：q100 型加固——BM25 强命中豁免（--rerank-guard）

> 遗留触发：m12 组合 11 救 1 失（q100：BM25 正确 top-1 被 LLM 挤走）。

**实现**（`bench.h` / `ingest_answer.cpp` / `main.cpp`）：LLM/便宜重排执行前，
若 BM25 终排序榜首的内容词分数 `top_content ≥ 阈值` → 记住榜首；重排后若其
不在首槽则前置保底（其余整体后移一位，选中项不丢）。阈值默认 **-1=关**，
`--rerank-guard X` 开启。选中执行逻辑重构为 LLM/便宜两路共用的
`apply_selection`（豁免、日志行为不变）。

**阈值校准（关键负发现）**：任务书建议"默认如 0.8"——实测本 benchmark 的
`top_content` 分布 **max=0.447、中位=0.213**（多词问题稀释 + 池内 df 影响，
单测里 0.833 的合成值在真实数据不出现）：0.5~0.8 的任何阈值都锁 0 题。
按校准数据取 **0.2**（p25=0.170 与 q100=0.213 之间）：锁 13 题。

**A/B 验收**（graph/sample50，off 复跑 0.443；组合 m12 0.604/11 救 1 失）：

| 组 | 覆盖率（n=48） | any-hit | 救回 | 丢失 |
|---|---|---|---|---|
| m12（无 guard，§10 复测基线） | 0.604 | 34/48 | 11 题 | q100 |
| m12 + --rerank-guard 0.2 | **0.646** | 36/48 | **12 题**（含 q100、q107） | **0 题** |

- **判据核验**：q100 挽回（金标 D4:15 回 top-1）✓；12 救题全部不回退 ✓
  （B 类选中序位 1/2/1/1，首槽锁定最多后移一位仍在 top-k）；
  意外收益 q107（此前被 LLM 位移影响的题，锁定后金标 D7:21 回 top-1）。
- **判决：任务 A 成立**，最终配置 = `--entity-pass-threshold 0.5
  --llm-rerank-all --rerank-guard 0.2`（覆盖率 0.646 = +0.203 vs off，
  judge 维度见 §10 同配置族 0.44）。
- 单测 `test_rerank_guard` 2 组（豁免关 = LLM 误判生效 / 豁免 0.8 = 保底）。

## 14. 任务 B：便宜近似 v1——特征逻辑重排器（--cheap-rerank）

**监督**（`cheap_rerank_train.py` + oracle 工具 `pools50` 模式）：
sample50 全部 50 题标准池特征导出（bm25/融合分量/ts/秩，逐行镜像 answer()
池构造）× m12 两轮运行日志的 LLM top-10 选中并集（跨运行 uid 噪声 → 任一
轮选中即正例；被展示从未选中 = 负例；从未展示 = 剔除）。训练对 1806
（正例 315 = 17.4%，42 题；剔除 714 条未见候选）。

**特征泄漏纪律**：特征只用引擎现成信号，不含任何 LLM 产物（LLM 仅作标签）。
**隔离**：sample50 单 case（conv-26），case 级隔离不可得 → 5-fold 按
question_id 分组（GroupKFold）。

**训练结果**（纯 Python 批量梯度下降逻辑回归，零依赖仿 GateModel 风格）：

- 5-fold CV：**AUC = 0.699** [0.716/0.756/0.770/0.630/0.623]；
  **正例 top-10 召回（宏平均）= 0.507** [0.586/0.501/0.561/0.442/0.445]。
- 权重方向可解释：bm25_rank/bm25_share 正（词面仍是主信号）、time/recency
  负（时近偏置抑金标的反特征）、ctx 负——模型学到的是"BM25 的修正项"，
  而非句级语义本身。
- 模型持久化 `cheap_model.json`（features/weights/bias/CV 指标）。

**判决实验**（--entity-pass-threshold 0.5 --cheap-rerank，零 LLM 零网络，
两次复跑）：

| 运行 | 覆盖率（n=48） | Δ | B 类 4 题金标进 top-k | 丢失 |
|---|---|---|---|---|
| cheap r1 | 0.490 | +0.047 | **1/4**（q154 位8） | 0 题 |
| cheap r2 | 0.484 | +0.042 | （q154，另 3 题在噪声带内外漂移） | 0 题 |

- 预注册线：≥0.55 且 B 类 ≥3/4 → 成立；<0.52 → 不成立。
- **判决：便宜近似 v1（特征逻辑回归）不成立**——两判据全不过
  （0.484~0.490 < 0.52；B 类 1/4）。交叉验证已预告：AUC 0.70 / top-10
  召回 0.51 的模型 imitation 不了句级判断（这正是 §0 天花板实验的
  另一面：句级收益来自 LLM 的语义判断本身，词面特征集承载不了它）。
- **最终形态建议（如实报告）**：产品形态走"**异步 LLM 池级打分 + 磁盘缓存**
  （DeepSeekClient 缓存机制已具，热路径近零成本）"；特征逻辑回归降级为
  可选项（本实现保留，--cheap-rerank 默认关）——它零成本零回归
  （+0.047、0 丢失），可作无网环境的兜底，但不构成主形态。
  蒸馏方向若续做，需比"池内引擎特征"更强的教师信号（如句向量），
  不在本任务数据条件内。

## 15. 蓝方自检（任务 A/B 追加）

7. **API 纪律**：任务 A/B 全程仅任务 A 的 guard A/B 与校准运行调用 LLM
   （标注与模型复用既有产物）；cheap 判决运行零 API。

即失锁）→ **上侧余量仅 0.013 是样本内事实，换样本可能位移**；0.15 侧代价
温和（-1 题）。0.2 位于 p25(0.170) 与 q100(0.213) 之间偏中，是三点中
"翻转最少+容错最宽"的选择；不选最大值逻辑而选稳健逻辑在本例与最优点
重合，如实披露。

### T2 cheap 档调优（目标：兜底抬向 m2 的 0.526，非翻案）

- 新特征 **ent_overlap** = 问题专名 token（大写非句首 len≥2，与实体通道
  同口径）出现在证据词集合中的比例。词面特征，无泄漏（标签来自 LLM）。
  训练后该特征权重 **-0.67**（负向！）：LLM 选中的是**不含实体名的改述
  金标**，专名重合证据恰是 BM25 已覆盖的"简单词面命中"——特征价值在
  "惩罚"而非"奖励"。
- 交叉验证：AUC 0.699→**0.710**，正例 top-10 召回 0.507→**0.514**
  （ imitation 指标微升，任务指标放大）。
- 端到端（零 API，两次复跑）：**0.573 / 0.536**（v1 = 0.484~0.490），
  +0.06~0.09；r1 时 B 类 3/4（q101/q154/q155）。r1 触预注册线（≥0.55 且
  ≥3/4）、r2 未触（0.536<0.55）——噪声带跨线。
- **判决：维持 v1 结论不翻案**（句级承载句级判断），但 cheap 档可用性
  大幅改善：无网兜底从 0.484 提到 **0.54~0.57 带**，已持平/超过 m2 单独的
  0.526。cheap 档定位从"实验残骸"升级为"合格兜底"。

### T3 LLM prompt 小消融（预注册：变体 ≥ 现版才换）

- 变体 = 指令追加"若某证据与问题存在关键词的精确重合（词面直接命中），
  必须将其保留在靠前位置，不得因其他证据语义相近而挤掉它"。
- A/B（同配置 guard 0.2）：现版 0.646/12 救 0 失 vs 变体 **0.667/13 救
  0 失**（新增 q156——A 类题金标被 LLM 直接选中入 top-k）。
- 变体 ⊇ 现版救回集且覆盖率更高 → **按预注册换为正形**（pin 指令并入
  唯一 prompt，旧版经 git 历史可复现）。

## 19. 蓝方自检（本轮追加）

1. **模式开关与旧开关并存的歧义面**：解析顺序无关（收集后消解），歧义
   只剩"同档多参数叠加"（如 --rerank llm --cheap-rerank x → 互斥报错，
   因映射到不同档）；`--llm-rerank 0`（历史关语义）不请求任何模式 →
   bm25 默认，与旧行为一致（0 即关）。别名永不再文档首页出现（usage
   标注 deprecated），新脚本一律用 --rerank。
2. **guard 扫参的多重比较风险**：三值只选其一，选据是"两侧容错"而非
   最大覆盖率（0.2 恰为最优点，已披露其与稳健判据重合；上侧余量 0.013
   的样本依赖写入 §18-T1，全量评测若 guard 失效应优先复查此处）。
3. **T2 新特征泄漏复查**：ent_overlap 全部来自问题文本（大写 token）与
   证据文本（词集合），零 LLM 产物；标签仍只来自 m12 日志。负向权重
   方向与机制理解一致（改述金标不含量词专名），非训练噪声
   （两折 AUC 均 >0.65）。
4. **prompt 变体的归因边界**：T3 变体与 guard 0.2 同时生效——变体的
   增益（+0.021）是在 guard 已兜底之上的增量（q156 是 LLM 主动选中，
   guard 无涉），归因干净；但"pin 指令 + guard"双保险可能在别的样本
   上过度保守（词面命中弱的相关证据被双重压前），全量时需盯"丢失"集合。
5. **cheap v2 触线未翻案的口径**：预注册线是"≥0.55 且 B 类 ≥3/4 成立"
   ——r1 触线但 r2 未触，按"噪声带跨线不翻案"纪律维持 v1 结论；
  如实报告 cheap 档的实际定位变化（兜底可用性成立）。
