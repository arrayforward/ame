# 句级语义的真实上限：oracle 测量（三实验）

> 前置：LLM 重排 spike（`llm_rerank_spike.md`）因结构性缺陷（33/50 题被实体
> 通道截走、到达者金标全在 top-20 窗外）测错了问题，用户裁决"还不到终局"。
> 本报告测真问题：**任何"句级相关性机制"的理论上限是多少？** 三个 oracle
> 实验全部用 LLM 当完美裁决器（上限语义：不计成本、假设产品机制达到 oracle
> 选中率），LLM 调用走 bench/cache 磁盘缓存，全部命令可复跑。
>
> 口径：coverage = |gold ∩ evidence_dia_ids| / |gold|，有金标题均值（n=48），
> 与历轮 A/B 完全一致；graph 后端 / sample50 / extractor rule / k=10 / k_pool=60。

## 0. 结论速览（三个上限数字）

| 实验 | 上限数字 | 一句话 |
|---|---|---|
| **E1 B 类池级重排** | **可回收 4/6**（金标在池 4/6，**在池者 LLM 选中率 4/4**） | 池级语义排序可行——B 类不是标注/噪声域，是窗口域 |
| **E2 A 类查询扩展** | **新进池 2/5**（严格）/ 池可达 3/5（含 q105 原池在池） | 方向对 2/5 成立、2/5 连扩展都跨不过（灰区偏负），代价是池噪声近翻倍 |
| **E3 实体通道审计** | **净贡献 ≈ 0**（覆盖 Δ+0.005 噪声内；judge 2/33 vs 反事实 4/33） | 不是资产也不是净害，但它是**墙**：把 E1 机制对 2/4 个可回收 B 题（q10/q155）锁在门外 |

**天花板：覆盖率 0.464（词级 plateau）→ 理论 ≈ 0.59**（B 类全回收 +4/48、
A 类全回收 +3/48；锚定本轮实测 C0=0.443，即 0.443+0.146=0.589）。
句级语义方向的理论上限约 **+0.13**（对 plateau），远超词级六轮的 +0.016——
**立项依据成立，且 E1 证明了主机制（池级语义打分）在池内 100% 可达。**

## 1. E1：B 类整池 LLM 重排天花板

**方法**：对 taxonomy B 类 6 题（金标在 lmem 口径池内但 rank>10），把标准管道
整池 60 条（dia_id + 首 200 字，融合序）一次性给 LLM，指令"选出对回答问题
最有用的前 10 条"，看金标是否入选 LLM 的 top-10。

**Prompt（全文）**：

```
你是检索重排器。给定一个问题（题号 <qid>）和 60 条候选证据（编号 E1..E60，
方括号内为来源标记，文本可能被截断）。
任务：选出对回答该问题最有用的前 10 条证据，按相关度从高到低给出编号。

问题: <question>

E1 [D3:13] <首 200 字>
...
E60 [..] <首 200 字>

只输出编号列表（形如: E3 E1 E7），恰好 10 个或少于 10 个（如果不够相关），
按相关度排序；若都不相关只输出 NONE。不要输出任何解释。
```

**逐题结果**（`bench/runs/oracle_ceiling/e1.ndjson`）：

| qid | 金标 | 金标 BM25 序 | 金标在池 | LLM top-10 入选 |
|---|---|---|---|---|
| q10 | D3:13 | 20 | ✓ | **✓** |
| q101 | D5:8 | 27 | ✓ | **✓** |
| q154 | D2:12 | 20 | ✓ | **✓** |
| q155 | D2:12 | 21 | ✓ | **✓** |
| q34 | D3:3, D9:2 | — | ✗（graph 池无） | ✗（oracle 也救不了） |
| q50 | D12:1 | — | ✗（graph 池无） | ✗（oracle 也救不了） |

**判读（预注册）**：进 ≥4/6 → 池级语义排序可行；≤2/6 → B 类是标注/噪声域。
**实测 4/6，且在池者 4/4 全选**——B 类可回收上限 = 4/6 = +4/48 = **+0.083**。
q34/q50 在 graph 口径金标根本不在 k_pool=60 池内（lmem 口径在），它们是
召回域问题（见 E2 的天花板逻辑），不归排序机制管。

**重要修正**：spike 的"N=20 窗口"漏掉的正是这 4 题——金标 BM25 序 20/21/27/20，
全部卡在 10~20/27 位；整池打分（或 N≥30 的窗口）即可触及。

## 2. E2：A 类 LLM 查询扩展天花板

**方法**：对 A 类 5 题（金标不在池），LLM 生成 3 条改写检索查询
（paraphrase/expansion），逐查询跑**同一词面召回**（同 SeedQuery 参数，
k_pool=60），看金标是否因此进池；同时计数进池的非金标噪声。

**Prompt（全文）**：

```
给定问题（题号 <qid>），生成 3 条改写检索查询（paraphrase / expansion，用于
关键词式召回，覆盖问题的不同语义侧面，可以换近义词、具体化或补充上下文）。
问题: <question>

只输出 3 行，格式：
Q1: <查询>
Q2: <查询>
Q3: <查询>
不要输出其他内容。
```

**逐题结果**（`bench/runs/oracle_ceiling/e2.ndjson`）：

| qid | 金标 | 原池金标 | 扩展新进池 | 命中查询 | 新噪声（非金标） | 并池 |
|---|---|---|---|---|---|---|
| q18 | D6:16, D4:6, D8:32（3 条） | 0 | **3 条全进** | 3/3 | 45 | 108 |
| q64 | D15:28 | 0 | **进** | 2/3 | 50 | 111 |
| q105 | D7:13 | **1（原池在，BM25 59）** | — | 1/3 | 56 | 116 |
| q3 | D2:8 | 0 | ✗ | 0/3 | 57 | 117 |
| q156 | D2:14 | 0 | ✗ | 0/3 | 63 | 123 |

**判读（预注册）**：≥3/5 进池 → 方向成立；≤1/5 → 跨不过。
**实测：严格口径（扩展因此新进）2/5；宽松口径（池可达，含 q105 原池在）3/5**
——踩线灰区。结构上可分：q18/q64 的鸿沟是**词汇层**（camping / Vivaldi·
Four Seasons·Baroque——扩展词即过桥，3/3 与 2/3 查询命中）；q3/q156 连
LLM 改写都跨不过（生成查询的召回池仍无金标），属于更深的鸿沟（需真向量
或推理链）。**代价量化：每题引入 45~63 条非金标新进池（池近乎翻倍）**——
扩展若进产品形态必须配套更强的排序门。
**A 类可回收上限 = 3/5 = +3/48 = +0.062**（q18/q64 靠扩展进池 + q105 靠
池内排序；q105 的归属见 §4 去重）。

## 3. E3：实体档案通道净贡献审计

**方法**：三次 CLI 运行（graph/sample50/judge llm，judge 同缓存条件）：
on = 生产路径（实体通道开）；attr = on + `--llm-rerank 20` 仅取逐题归因日志
（哪些题被实体通道提前返回）；off = `--entity-profile off` 反事实
（标准管道假设表现）。截走判定用合并版二进制的诊断日志
（`[llm-rerank] <qid>: 实体档案通道提前返回，未重排`），非猜测。

**结果**：

- **截走 33/50 题**（66%——与 spike 一致）。
- 截走题 coverage：通道受益 1 题（q160：on 1.0 vs off 0.0）/ 通道受损 1 题
  （q107：on 0.0 vs off 1.0）/ 持平 31 题；全样本 on=0.443 vs off=0.448，
  Δ=+0.005 在噪声带内——**覆盖率维度净贡献 ≈ 0**。
- 截走题 judge 答对：on（通道实际作答）**2/33**（q12、q46）vs off（标准管道
  反事实）**4/33**（q100、q108、q12、q158）——judge 维度通道略负（-2 题），
  但它答的题多半本来也答不对（33 题里 31 题覆盖持平且 judge=0）。
- q104 被截走但通道处理正确（金标 D7:11 命中）——graph 口径下 q104 不是
  近失题（spike 的"q104 型"结论修正为 lmem 口径现象）。

**净贡献结论：它不是资产（judge 2/33）、也不是净害（覆盖噪声内），但它是
墙**——66% 的题绕过了 BM25 终排与任何未来的池级语义打分；特别是 E1 证明
可回收的 4 个 B 题里 **q10/q155 被它截走**（它的池内排序同样把金标排在
top-10 外，且池内无 LLM 重排）。

## 4. 天花板总结

锚定：本轮实测 C0=0.443（与记录基线 0.448 同噪声带）；词级 plateau 0.464。

| 来源 | 可回收 | 覆盖率增量 | 依赖 |
|---|---|---|---|
| B 类池级重排（E1） | 4/6 | +4/48 = **+0.083** | q10/q155 需实体通道放行（改造或池内重排） |
| A 类查询扩展（E2 严格） | 2/5 | +2/48 = +0.042 | 池噪声近翻倍，需排序门 |
| A 类 q105（E2 池检查） | 1/5 | +1/48 = +0.021 | 仅池级排序即可（金标原池在，BM25 59） |
| A 类合计 | 3/5 | **+3/48 = +0.062** | |
| **合计天花板** | | **+0.146** | |
| **0.464 → 理论上限** | | **≈ 0.589**（C0 口径 0.443+0.146） | |

说明：这是**上限**（oracle 假设产品机制达到 LLM 选中率）；E1 在池选中率 4/4
支持该假设对"池级打分"近似成立，E2 回收的金标进的是翻倍噪声池，实际选中率
会低于 1.0——乐观偏差方向已在蓝方 §6 量化声明。q34/q50（B 类 2 题）、
q3/q156（A 类 2 题）四题**不在任何句级机制的上限内**（金标不在池且扩展
也够不到），它们划定了句级范式的真实边界：≈4/48 ≈ 0.08 永久不可达。

## 5. 机制设计建议（按上限数据排优先级）

1. **池级语义打分（预期 +0.083，最高优先）**。E1 已证明：金标在池时
   LLM 整池 top-10 选中率 4/4。产品形态两条路：(a) 全池 LLM 打分——
   成本 50 题 × 60 池 ≈ 300k tokens/轮，贵但判决实验说明收益上限够格做
   蒸馏；(b) 蒸馏小模型/异步打分——先用全池 LLM 打分造监督数据
   （本报告的 e1.ndjson 即首批标注），这正是 spike 判决线"≥+0.05 触发
   便宜近似设计"的触发条件（oracle 版 +0.083 ≥ +0.05）。
   工程前提 = 第 2 项。
2. **实体通道改造（解锁 +0.042 中属于 q10/q155 的部分，纯工程零 LLM）**。
   不是拆通道（E3：覆盖净贡献 0、q104/q160 靠它），而是**把池级打分也挂进
   实体通道的候选排序**（它的 lookup 池同样 60+ 条、同样 BM25 终排），或
   低置信时放行标准管道。收益 = 让 E1 的 4/4 覆盖到被截走的题。
3. **LLM 查询扩展（预期 +0.042，最低优先）**。2/5 成功率、池噪声近翻倍、
   每题 2 次 LLM 调用；只在第 1 项落地后作为**扩池的增量**考虑
   （先扩展进池、再由池级打分把关噪声）。q3/q156 的失败提示该机制天花板
   低，不值得单独立项。

## 6. 蓝方自检逐条

1. **LLM"相关"≠金标口径的偏差方向（双向计数）**：
   - *LLM 认为相关但金标没有（false positive）*：E1 共 60 个 LLM 选中位
     （6 题 × 10），其中非金标 56 个——但这是 top-10 的正常构成，coverage
     口径只问金标在不在，不产生假阳性损失；E2 的对应物是**进池非金标噪声
     45~63 条/题**（已量化，进报告 §2）。
   - *金标在但 LLM 不选（false negative）*：E1 在池金标 4 条，落选 0 条
     （0/4）；spike 窗口版 r2 的 13 置顶里金标落选若干（窗口所致，非本实验）。
   - 偏差方向结论：oracle 在"池内选金标"上无实测偏差，上限数字不因该偏差
     膨胀。
2. **E2 假阳性**：每题扩展并池新增 45~63 条非金标（q156 最多 63，池 60→123）。
   若扩展与池级打分组合，排序门面对双倍池——这是 E2 收益 +0.042 的隐性
   成本，已在优先级第 3 条降级处理。
3. **E2 召回口径**：扩展查询未继承原题时间过滤（parse_relative 锚点），
   可能引入时间窗外事件——只影响"进池"判定不影响本实验结论（金标判定
   用 dia_id 集合）；产品上扩展查询的时间处理需单独设计。
4. **E3 反事实口径说明**：off 运行 = 同摄入同 recall 仅关实体通道，是
   "标准管道假设表现"而非真实历史路径（这些题生产上从未走过标准管道）；
   uid 噪声使单题对比有 ±1 题翻转风险（q32 型），故净贡献结论锚定
   "33 题聚合 + 噪声带"而非单题。judge 维度 n=33 功效有限（2 vs 4），
   只作方向参考。
5. **缓存防污染**：全部 LLM 调用经 DeepSeekClient，缓存键 = FNV-1a
   （模型+消息+选项）；prompt 含题 id + 池内容（dia_id+文本）/生成查询，
   与历史 answer/judge 缓存零碰撞。实测 e1/e2 全 miss（全新 prompt），
   e3_off 的 judge 与 e3_on 同 prompt 命中 13/50。
6. **oracle 上限的乐观性**：假设产品机制 = LLM 选中率。对 E1（在池 4/4）
   近似成立；对 E2 回收（噪声翻倍池）系统性偏乐观——0.589 应读作
   "≈0.55~0.59 区间上限"。词级六轮纪律（预注册线、噪声带 ±0.005）沿用。

## 7. 复跑命令

```bash
# 构建 oracle 工具（一次性；引擎代码零改动，纯脚本侧链接 libame_*.a）
export PATH="$(dirname $(which g++)):$PATH"
INCS=""; for d in core storage time vector keyword extractor entity graph_writer \
  seed diffusion rerank thinker feedback learning engine bench llm; do INCS="$INCS -I$d/include"; done
LIBS=$(find build-win -name "libame_*.a" | sort -r | tr '\n' ' ')
g++ -O2 -std=c++17 -D_GNU_SOURCE -D_DEFAULT_SOURCE -D_POSIX_C_SOURCE=200809L \
  -include D:/agent/memory/tmp_dbg/win_compat.h $INCS \
  bench/scripts/oracle_ceiling.cpp $LIBS $LIBS -o bench/scripts/oracle_ceiling.exe

# 三实验（LLM 走 bench/cache；E1/E2 约 11 次调用，E3 judge 最多 100 次、热缓存部分命中）
./bench/scripts/oracle_ceiling.exe pools bench/runs/oracle_ceiling/pools.ndjson
./bench/scripts/oracle_ceiling.exe e1    bench/runs/oracle_ceiling/e1.ndjson
./bench/scripts/oracle_ceiling.exe e2    bench/runs/oracle_ceiling/e2.ndjson
B=./build-win/bench/ame_bench.exe; D="--dataset locomo --data bench/data/locomo10.json \
  --question-ids bench/data/locomo_sample50.json --extractor rule --answer baseline --k 10"
$B $D --judge llm --dump bench/runs/oracle_ceiling/e3_on.ndjson   > .../e3_on.out  2> .../e3_on.log
$B $D --judge f1 --llm-rerank 20 > .../e3_attr.out 2> .../e3_attr.log   # 仅归因日志
$B $D --judge llm --entity-profile off --dump .../e3_off.ndjson > .../e3_off.out 2> .../e3_off.log

# 汇总（E1/E2 逐题表 + E3 审计 + 天花板计算）
python bench/scripts/oracle_ceiling_analyze.py
```
