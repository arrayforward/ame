## 1. 经济性三档判读（"每单位覆盖率的花费"）

| 经济性档 | 档位内排序（覆盖率 / 每题成本 / 延迟） | 判读 |
|---|---|---|
| **零 LLM** | AME svec 0.578 ≈ cheap 0.557 ≫ 自参照最佳 0.479（bm25-turn）/ 0.469（bge-large 337MB）/ 0.347（dense-turn） | **AME 零-LLM 记忆层大胜行业默认形态**：比同模型 dense-turn +0.231（管线红利 > 模型规模红利：large +0.122），比行业最佳词面 +0.078；成本全部为零 |
| **写时 LLM** | Mem0 0.703 @ 写 47min+838 调用+~$0.01/题摊销 + 查 2.25s | Mem0 覆盖率全场最高，但**每 +0.01 覆盖率的边际成本三个数量级于 AME**：vs AME svec 差 -0.125 而写成本高 ~350×、查询慢 ~100×；vs AME llm 仅 +0.031 而 AME 写时零成本 |
| **查询时 LLM** | AME llm 0.672 @ ~6-7k tok/题（~$0.002/题，缓存后近零） | AME 该档无商业对手实测（Zep 未跑通）；官方口径下 Zep 端到端 80%+ 是"写时+查询时 LLM"双档产品，与我们单档不可直接比 |

**核心结论**：AME 在"零 LLM"和"查询时 LLM"两个经济性档位都给出了同档位最强的覆盖率；行业最优 Mem0 靠"写时 LLM 事实提取"多拿 +0.03~+0.13 覆盖率，代价是写入管线的全量成本——**这是形态差异不是工程差距**，是否引入写时提取是 AME 的下一形态决策（本期只记录事实）。

## 2. AME 当前定位（一页）

- **零-LLM 档（离线兜底/端侧形态）**：cheap 0.557 / svec 0.578，无任何推理成本、34MB 级本地模型（svec），显著强于一切同成本行业参照（+0.08~+0.23）。**这是 AME 对行业产品的核心卖点档**。
- **查询侧一点 LLM 档（在线推荐形态）**：llm 0.672 + judge 0.64（作答质量修复后），写时零成本、每题一次全池打分；vs Mem0 0.703 差 -0.031，但 Mem0 每案要预付 47min 写入管线。**检索质量同级，成本结构碾压**。
- **已知缺口**：写时 LLM 事实提取形态（Mem0 靠它领先）AME 没有；cat5 对抗题弃答纪律（P1 本轮试过、按预注册回退，见 §9）。
- **研究期边界**：以上全部 sample50 抽样结论；uid 噪声带 ±0.01~0.04 已披露；全量评测属发布期。

## 3. 蓝方终稿自检

1. 双口径分层（组件层 coverage / 系统层 judge）分开标注，judge 只在 AME 臂间可比（Mem0 无同口径 judge）。
2. Mem0 事实级粒度（409 记忆 tag 单 dia_id）vs AME 轮级：top-10 语义密度不等，方向有利于 Mem0，已披露不修正。
3. 行业公开数字三重口径不可比面（量/后端/指标）逐项标注，不进对照判读。
4. dense-window 粒度假象与等份额控制已证伪其表面 0.773。
5. 经济性成本为实测/估账混合：Mem0 写成本实测（47min/838 调用）、美元按 deepseek-chat 官方价假设；AME token 为 prompt 实测估算——均以"量级"表述。

## 2. 判读：AME 在哪个经济性档位打赢谁

1. **零-LLM 档：AME 全面胜**。AME cheap 0.557 / svec 0.578 vs 行业裸 RAG 自参照
   dense-turn 0.347（+0.21~+0.23）；vs 词面参照 bm25-turn 0.479 亦胜。零推理
   成本下 AME 的记忆层（融合特征+图扩散+实体通道+学习重排）显著强于
   "切块+向量"的默认形态——与 industry_baseline.md 结论互证。
2. **写时-LLM 档：Mem0 以重成本换 +0.03~+0.13**。Mem0 0.703 是全部臂最高，
   但它花 47 分钟/838 次 LLM 调用完成写入（每案），查询中位 2.25s/题；同档
   位对比：AME svec 0.578（写时仅 ~8s 本地 embed、查询 21ms）覆盖率差
   -0.125，**但写入成本差 ~350 倍、查询延迟差 ~100 倍**；AME llm 0.672 与
   Mem0 差 -0.031，而 AME llm **写时零成本**（无提取管线，直接索引原文）。
   覆盖率每 +0.01 的边际成本：Mem0 ≫ AME llm ≫ AME svec。
3. **查询时-LLM 档**：AME llm 0.672 + 作答质量修复后 judge 0.64（answer_quality.md）
   是"查询时 LLM"形态里成本最优的（每题一次全池打分 ~4k tok，写时免费）。
4. **产品级结论（研究期）**：若目标"覆盖率尽量高且不在乎写入成本"→ Mem0 形态
   最优（0.703）；若目标"零/低 LLM 成本的记忆层"→ AME cheap/svec 显著强于
   同成本的一切行业参照；AME 的空档在"写时-LLM 提取"（Mem0 靠它拿到
   +0.125），这是后续可评估引入的形态——**本期只记录事实，不改 AME**。

## 3. Mem0 臂实现与口径映射（复现路径）

- 写入：`m.add([{user 轮文本}], user_id="conv-26", metadata={"dia_id": D#})`
  （mem0 2.2.1 强制 user_id；内部 LLM 事实提取，~2 次调用/轮）。
- 查询：`m.search(question, limit=10, filters={user_id})` → top-10 记忆，取
  `metadata.dia_id` 并集计覆盖率。
- **粒度差异披露**：Mem0 记忆是**事实级**（409 条 distilled facts）非轮级
  （AME/参照臂是 419 轮取 10）。top-10 记忆 ≠ top-10 轮：单轮可产出多条记忆，
  记忆的信息密度高于轮——该差异对 Mem0 **有利**（10 条事实覆盖的 dia 多样性
  通常 ≥ 10 条原文），如实标注不修正。
- 复跑：`bench/venv-commercial/Scripts/python.exe bench/scripts/commercial_mem0.py`
  （全量重写 qdrant）；`--search-only` 只查不重写。

## 4. 成本与延迟账（实测）

| 项 | Mem0 臂 | 备注 |
|---|---|---|
| 写入 | 47min/整案（419 轮，838 次 LLM 调用） | ~6.5s/轮（DeepSeek 思考型输出） |
| 写入 token | 估 ~0.5-0.7M input + ~84k output | 按调用次数×典型 prompt 长度估 |
| 写入美元 | **~$0.3-0.5/整案**（deepseek-chat 官方价 $0.27/M in、$1.10/M out 假设） | 价格随官方变动，以 token 数为准 |
| 每题分摊 | ~$0.01（写） | 查询无 LLM |
| 查询延迟 | 中位 2254ms / p90 2605ms | **无 LLM 调用的实测**（证据：缓存文件数恰=2×419，search 零 chat 调用）——2.25s 为本链路程实测开销 |

## 6. 蓝方自检

1. **dia_id 双口径**：宽松 = top-10 记忆 metadata.dia_id（列表则并集，含跨轮
   合并记忆挂的全部 dia_id）；严格 = 仅单 dia_id 记忆。**实测两口径同值
   0.703**——写入过程中未产生挂多 dia_id 的合并记忆（409 条均单挂），故
   合并污染未发生；粒度差异（事实级≠轮级）在 §3 披露且不修正。
2. **各家 top-k 语义差异**：Mem0 limit=10 是 10 条事实（浓缩），AME/参照臂
   是 10 轮（原文）——信息密度不对等，对 Mem0 有利方向已标注；AME 侧
   entity-pass 并入候选使其 top-10 偶尔 >10 个不同 dia，两向差异不系统性
   偏向一方，披露为止。
3. **LLM 后端不可比面**：Mem0 臂与我们全部 AME 臂同用 DeepSeek（同 key 只读）
   + 本地 bge 嵌入——**臂间可比**；Zep 官方数字用 GPT-4o 后端 → 只在 §5 作
   量级参照，不进对照表判读。
4. **缓存复跑**：shim 按请求体 sha1 磁盘缓存；实测发现 **mem0 增量提取的
   prompt 依赖当前记忆库状态**（事实更新检查携带已有记忆），逐轮 add 的
   顺序重放无法命中缓存（第二轮近乎全量重算，838 新文件）——这是 Mem0
   "写时 LLM"形态的成本结构事实，如实披露；AME 各臂无此问题（检索确定性
   + 缓存键纯文本哈希）。
5. **环境隔离**：venv（gitignore）、PostHog 遥测警告出现但未拦截（mem0
   默认开 telemetry，未配置 key 故无上报出口）；spaCy/fastembed 可选件缺失
   只关停了 mem0 的 BM25 关键词通道（其语义通道不受影响），如实记录。
6. **研究期纪律**：本期全部结论基于 sample50（n=48）；不在本报告列全量
   评测计划项；所有数字可用 §3 命令复现（LLM 缓存命中后写入重放仍需
   ~45min，查询秒级）。

# 收尾轮拾漏记录（P1/P2，预注册各自独立判）

## 9. P1 cat5 弃答纪律（judge 侧）——按预注册回退

**做法**：`LlmAnswerer` system prompt 加弃答纪律（错误前提/证据不足 → 只输出
NO INFORMATION）。llm 冻结配置（entity-pass 0.5 + guard 0.2 + answer llm +
judge llm）A/B 两次复跑。

| 臂 | judge | 覆盖率 | any-hit | cat5 弃答 | cat1-4 弃答率 |
|---|---|---|---|---|---|
| 基线（fix_r1/r2） | 0.640 / 0.620 | 0.667 / 0.646 | 37 / 36 | 3 / 4（共 10） | 3/40（7.5%）×2 |
| **P1（p1_r1/r2）** | 0.640 / 0.720（均值 0.680） | 0.646 / 0.635 | 36 / 35 | **8 / 9** | **11/40、9/40（22.5~27.5%）** |

**预注册线**：两次均值 judge ≥ 0.70 且覆盖率在历史带内且 cat1-4 弃答率容差
+5pp。实测均值 0.680 未过线；**误伤面 3 倍上升**（7.5%→22.5~27.5%）超容差；
any-hit 微降。**判定：回退**（prompt 已还原，git diff 为空）。机制验证成功
（cat5 弃答 3.5→8.5/10，judge r2 触及 0.72）但净收益为噪声带跨线、误伤真实，
按纪律不并入。cat5 剩余 1~2 题硬答与"部分相关即给最可能答案"的指令语义纠缠，
留给发布期以更精细的判分侧方案处理。

## 10. P2 覆盖率拾漏——两旋钮均不采纳，冻结值复证

判据（预注册）：覆盖率稳定上升 > +0.01 且 any-hit 零减少且 judge 不降 >0.02，
各旋钮独立判。基线 = llm 冻结带（coverage 0.646~0.672，any-hit 36~37/48，
judge 0.62~0.64）。

| 旋钮 | 覆盖率 | any-hit | judge | 判定 |
|---|---|---|---|---|
| (a) k 10→15 | 0.651 | 36/48 | 0.680 | **不采纳**：Δ≈0（噪声内），无稳定增益 |
| (b) entity-pass 0.3 | 0.635 | 35/48 | 0.620 | **不采纳**：双降 |
| (b) entity-pass 0.7 | 0.635 | 35/48 | 0.700 | **不采纳**：judge 0.70 为单次噪声，coverage/any-hit 双降 |

**结论**：entity-pass 0.5（pre-llm 时代选定值）在 llm 档重扫 0.3/0.5/0.7 后
仍为最优——llm 重排在场未使最优值移动；k=10 不变。冻结配置维持，P2 零代码
改动。
